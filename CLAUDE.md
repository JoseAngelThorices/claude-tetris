# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the game

No build step or dependencies. Open directly or serve with any static server:

```bash
open index.html                  # macOS direct open
python3 -m http.server 8000      # then visit http://localhost:8000
```

## Architecture

Three files, no framework, no bundler:

- **`index.html`** — DOM structure: `<canvas id="board">` (300×600px) for the playfield, `<canvas id="next-canvas">` (120×120px) for the preview, sidebar HUD (`#score`, `#lines`, `#level`), skin selector container `#skin-picker` (buttons generated by game.js), light/dark toggle `#theme-toggle`, a dedicated pause menu `#pause-menu` (`#resume-btn`, `#pause-restart-btn`, `#controls-btn` + `#pause-controls`, `#start-level-select`), and the `#overlay` used for START and GAME OVER (`data-mode="start|gameover"`). Overlay contents: `#overlay-title`, `#overlay-score`, `#overlay-msgs` (record messages), `#name-form`/`#name-input`/`#save-btn`, `#records-section` (`#records-body` table, `#best-combo`, `#max-lines`, `#reset-records-btn`, `#reset-confirm` with `#reset-yes-btn`/`#reset-no-btn`) and `#restart-btn` (Jugar/Reiniciar).
- **`style.css`** — Dark/retro arcade theme with a light mode (`body.light-mode`); uses CSS variables (incl. `--accent`, `--danger`, `--highlight-text`, `--highlight-bg`, `--input-bg`, redefined in `body.light-mode`), flexbox, and `backdrop-filter` on overlays. Canvas background/border read `var(--skin-board-bg, var(--canvas-bg))` and `var(--skin-accent, var(--border))`. Pause menu styles: `.pause-box`, `.menu-btn`, `.pause-controls`, `.level-select`, `.menu-hint`. Visibility of overlay sub-elements uses the `hidden` attribute (`[hidden]{display:none!important}`); the overlays themselves use `.overlay.hidden`.
- **`game.js`** — All game logic (~1050 lines, `'use strict'`, no modules).

### game.js internals

| Concern | Key identifiers |
|---|---|
| Board state | `board` — `ROWS×COLS` matrix; `0` = empty, `1–8` = piece color index (8 = N "tuerca") |
| Piece representation | `{ type, shape, x, y }` where `shape` is a 2-D matrix |
| Rotation | `rotateCW(shape)` — transpose + reverse; `tryRotate()` applies wall kicks `[0,±1,±2]` |
| Collision | `collide(shape, ox, oy)` — checks bounds and board occupancy |
| Game loop | `loop(ts)` via `requestAnimationFrame`; `dropAccum` tracks elapsed ms against `dropInterval` |
| Line clear | `clearLines()` — iterates board bottom-up, splices full rows, prepends empty row; returns number of lines cleared |
| Combo | `combo`, `maxCombo` — updated in `lockPiece()` (see definition below) |
| Scoring | `LINE_SCORES = [0,100,300,500,800]` × `level`; hard drop +2/cell, soft drop +1/row |
| Speed | `intervalForLevel(lv)` = `max(100, 1000 − (lv−1) × 90)` ms; `computeLevel()` = `max(startLevel, floor(lines/10) + 1)` |
| Ghost piece | `ghostY()` — projects current piece down until collision; drawn at `currentSkin.ghostAlpha` (0.2–0.3) |
| Rendering | `drawCell(context, col, row, colorIndex, size, alpha)` → `currentSkin.drawBlock(...)`; `drawGrid()`, `draw()`, `drawNext()`; `repaint()` redraws both canvases immediately (used on skin/theme change while paused or game over) |
| Skins | `SKINS`, `currentSkin`, `currentSkinId`, `applySkin(id)`, `loadSkinId()`, `saveSkinId(id)`, `buildSkinPicker()`, `SKIN_STORAGE_KEY` (`'tetris-skin'`), `DEFAULT_SKIN` (`'retro'`) |
| Skin helpers | `shade(hex, amount)` (memoized lighten/darken), `withAlpha(hex, a)`, `roundRectPath()` (`roundRect` with `quadraticCurveTo` fallback), `getSprite(key, w, h, render)` + `spriteCache` (offscreen canvases), `neonSprite()`, `pixelSprite()`, `PIXEL_PATTERN` |
| UI theme | `applyTheme(isLight)` toggles `body.light-mode`, caches `themeGridColor` from `--grid-line`; stored in `localStorage['tetris-theme']` |
| Starting level | `startLevel` (1–`MAX_START_LEVEL`=15), set via `setStartLevel()` from `#start-level-select`, persisted in `localStorage['tetris-start-level']`; applied on next `init()` |
| Pause menu | `P`/`Escape` → `togglePause()` → `pauseGame()` / `resumeGame()`; `restartGame()`; `openPauseMenu()` / `closePauseMenu()`; `handleMenuKey(e)` (↑/↓/Tab focus cycling, ←/→ change level) |
| Input lock | While `paused`, game keys never reach the game. `heldKeys` / `suppressedKeys`: keys still held when the menu closes are ignored until `keyup`, so Enter/Space/arrows used in the menu don't leak into gameplay |
| State flags | `started` (false on start screen), `paused`, `gameOver`, `animId` (RAF handle; always cancelled before requesting a new one), `lastGame` (`{ entry, saved, newBestCombo, newMaxLines }` for the finished game) |
| Overlay | `#overlay` for start screen and game over: `showOverlay(mode)` (`'start'`/`'gameover'`), `hideOverlay()`. Pause uses the separate `#pause-menu` |
| Records storage | `RECORDS_KEY` (`'tetris-records'`), `LAST_NAME_KEY` (`'tetris-last-name'`), `TOP_SIZE` (5), `NAME_MAX` (12), `DEFAULT_NAME`; `loadRecords()` (try/catch + shape validation via `sanitizeEntry()`, falls back to `emptyRecords()`), `saveRecords()`, `clearRecords()`, `loadLastName()`, `saveLastName()`, `cleanName()` |
| Records logic | `qualifiesForTop(score, top)`, `insertEntry(top, entry)` (non-mutating, returns `{ top, index }`), `saveCurrentRecord()`, `resetRecords()` |
| Records UI | `renderRecords(records, highlightIndex)` (DOM built with `textContent` only — never `innerHTML` with user data), `setMessages(msgs)`, `refreshRecordsView()` (table + messages + name form for the current overlay mode) |

### Game flow

Page load → `showStartScreen()` (empty board, no RAF loop, overlay in `start` mode with the records table). "Jugar" button or Enter → `init()` → `resetState()` + `spawn()` → `requestAnimationFrame(loop)`. `init()` always cancels the previous RAF and blurs the focused element, so restarting never duplicates the loop. Each frame: accumulate dt → auto-drop or `lockPiece()` → `draw()`. `lockPiece()` = `merge()` + `clearLines()` + combo update + `spawn()`. If `spawn()` immediately collides → `endGame()`. Resuming from pause resets `lastTime` to `performance.now()` (and `loop` clamps `dt ≥ 0`) so there is no drop jump.

Keyboard: while an `<input>` has focus the global `keydown` handler ignores every key. Outside a game (start screen / game over) only Enter is handled: it starts a game, or focuses `#name-input` if a record is still pending to be saved. During a game `P`/`Escape` toggle the pause menu (`pauseGame()` is a no-op before `started` or after `gameOver`).

### Records (localStorage)

Stored under `tetris-records` as `{ top: [{ name, score, lines, level, combo, date }], bestCombo, maxLines }`; last used name under `tetris-last-name`. If storage is missing, corrupt or throws, the game runs without records.

- **Combo**: number of consecutive locked pieces that clear at least one line. It resets to 0 when a piece locks without clearing. `maxCombo` is the highest combo in the current game.
- **Líneas máximas**: highest total `lines` reached in a single game.
- `bestCombo` and `maxLines` are all-time records independent of the top 5; `endGame()` saves them whenever they are beaten.
- **Top 5**: a game qualifies when `score > 0` and (fewer than 5 entries or `score` > 5th score). On game over a qualifying score shows `#name-form` (default = last used name or `"Jugador"`, trimmed, max 12 chars) and a highlighted preview row; submitting saves it and keeps the row highlighted. Ties go below existing entries.
- "Resetear records" asks for confirmation inside the overlay, removes `tetris-records` (keeps last name) and refreshes the visible table.

## Tunable constants (top of game.js)

`COLS` (10), `ROWS` (20), `BLOCK` (30 px), `LINE_SCORES`. Piece colors live in each skin's `colors` array (see below). If you change `COLS`/`ROWS`/`BLOCK`, update the canvas `width`/`height` attributes in `index.html` to match (`COLS×BLOCK` and `ROWS×BLOCK`).

## Skins (canvas) vs. theme (UI)

- **Skin** controls everything drawn on the canvases (board, grid, ghost, current piece, next preview) plus the canvas background/border. **Theme** (light/dark toggle) controls the rest of the UI.
- A skin field set to `null` inherits from the theme: Retro uses `null` for `boardBg`, `gridColor` and `accent`, so it looks exactly like the original style in both light and dark mode. Other skins impose their own canvas background regardless of theme.
- `applySkin(id)` sets `--skin-board-bg` / `--skin-accent` on `<body>` (removed when `null`), updates `aria-pressed` on the buttons and calls `repaint()`. Preference is stored in `localStorage['tetris-skin']`; reads/writes are wrapped in try/catch and unknown values fall back to `retro`.
- Keyboard: during a game `P`/`Escape` toggle pause; otherwise, while any `button/select` outside the pause menu has focus, the game keys are ignored; skin and theme buttons blur themselves after a click, so arrows/Space go back to the game.
- Built-in skins: `retro` (flat squares + top highlight), `neon` (black board, glow via `shadowBlur`/`shadowColor` pre-rendered once per color into offscreen sprites, drawn with `'lighter'` compositing), `pastel` (soft palette, rounded blocks with a small margin), `pixel` (10×10 texture from `PIXEL_PATTERN`: light top/left, dark bottom/right, dithered interior; cached per color).

### Adding a skin

Add one entry to `SKINS` in game.js; the selector button is generated automatically:

```js
mySkin: {
  name: 'My skin',                 // button label
  colors: [null, I, O, T, S, Z, J, L, N], // '#rrggbb', indexed 1–8
  boardBg: '#000000',              // or null → theme --canvas-bg
  gridColor: '#111111',            // or null → theme --grid-line
  accent: '#ff00ff',               // canvas border / selected button; or null
  ghostAlpha: 0.25,
  drawBlock(ctx, x, y, size, color, alpha) { /* pixel coords; wrap in ctx.save()/restore() */ },
},
```

Rules: no per-skin conditionals in the drawing code — all differences go through the skin object. Anything expensive (shadowBlur, textures) should be pre-rendered with `getSprite()`. Colors must be 6-digit hex if you use `shade()`/`withAlpha()`.
